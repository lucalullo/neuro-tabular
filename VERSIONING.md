# Versioning policy and current candidate

The public policies in docs/policies/VERSIONING_POLICY.md and PERSISTENCE_POLICY.md
remain authoritative. The published baseline 1.0.3, its tag and artifacts are
immutable. The maintainer explicitly selected 2.0.0 as a major maturity and
consolidation milestone. The engineering scope is compatible maintenance:
repository privacy, numerical-input correctness and release quality. The number
does not imply new architecture, predictive accuracy or a deliberate API break.
Valid-input calculations and defaults remain unchanged.

Version module, pyproject, CITATION, test and release notes identify 2.0.0.
No publication date or remote publication approval is asserted. Version 2.0.0
requires final build verification, exact-content CI and maintainer authorization.
Local builds have source/artifact hashes; an unchanged version string never
permits replacement of published artifacts. No new performance claim is made.

The maintainer selected 2.0.0 as the next final maturity milestone; see the canonical versioning policy for compatibility, selective future releases and critical-fix exceptions. This does not claim new predictive algorithms or authorize publication.
